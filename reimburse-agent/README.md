# 报销审核 AI 同事

## 配置密钥并启动（Windows PowerShell）

先安装 Git 和 Go 1.25 或更高版本，并确保可以联网下载 Go 依赖、访问模型接口。在 PowerShell 中执行下面的命令。

```powershell
git clone https://github.com/cococoaa/AI-coworker.git
cd AI-coworker\reimburse-agent

$env:DEEPSEEK_API_KEY = "替换为自己的网关密钥"
$env:ANTHROPIC_API_KEY = "替换为自己的网关密钥"

go run ./cmd/serve -addr 127.0.0.1:8790 -config config.example.json -data data -mcp-data data/world.json -people people.json -local-operator E3001
```

已有代码时，直接进入克隆目录中的 `reimburse-agent` 文件夹，再设置环境变量并执行启动命令。首次启动会下载依赖和编译，请等待终端显示监听地址。

启动后，在运行服务的电脑上打开 [http://127.0.0.1:8790](http://127.0.0.1:8790)。

**密钥必须与接口地址匹配。** 当前 `config.example.json` 使用第三方网关 `https://api.openai-next.com`。如果同一把网关密钥支持两个模型，可以给两个变量填写相同的值。使用 DeepSeek、Anthropic 官方密钥或其他网关时，先调整配置文件中对应的 `base_url`、`model` 等参数。

环境变量仅对当前 PowerShell 窗口及其启动的程序生效。修改密钥后，在运行旧服务的窗口按 `Ctrl+C`，再从设置好密钥的窗口启动。密钥通过环境变量提供。

| 启动参数 | 用途 |
| --- | --- |
| `-addr 127.0.0.1:8790` | 本机访问地址和端口 |
| `-config config.example.json` | 模型接口和环境变量名称配置 |
| `-data data` | 加载仓库中的测试数据 |
| `-mcp-data data/world.json` | 使用模拟发票、企业和历史记录核验库 |
| `-people people.json` | 加载人员和权限名单 |
| `-local-operator E3001` | 将本机操作身份绑定为王会计，支持人工复核；申请人工号在表单中另填 |

需要在本机演示中切换复核人、并为留空的申请单号自动生成演示编号时，可在命令末尾追加 `-local-demo-operators`。

这套启动方式调用真实模型，并使用模拟核验数据。新上传发票是否通过还取决于核验库记录、材料完整性和业务规则。交通报销需同时提供行程凭证。

### 本机运行与远程部署的访问令牌

本机按上面的 `-addr 127.0.0.1:8790` 启动时，系统跳过网页登录令牌校验。其他人克隆仓库后在自己的电脑上使用同样的命令，也可以直接打开页面。

系统根据服务的监听地址决定是否启用登录。监听 `0.0.0.0` 等非回环地址时，必须配置访问令牌。魔搭部署默认监听 `0.0.0.0:7860`，因此会显示“请粘贴访问令牌”的登录页。

| 配置 | 用途 |
| --- | --- |
| `DEEPSEEK_API_KEY`、`ANTHROPIC_API_KEY` | 供后端调用模型接口 |
| `REIMBURSE_UI_TOKENS` | 控制网页登录，并将访问身份绑定到人员名单中的工号 |

**魔搭配置**：在创空间的密文设置中添加 `REIMBURSE_UI_TOKENS`，值使用下面的格式，将占位内容替换为至少16位的随机令牌，并重启服务使配置生效。

```text
E3001:替换为至少16位随机令牌
```

`E3001` 对应 `people.json` 中的王会计。登录框只填写冒号后面的令牌内容。
#### 共享演示登录

打开 [AI-worker 创空间](https://modelscope.cn/studios/zkkwin/AI-worker)，在应用登录框粘贴下面的令牌。

```text
62010e40f2154004b6034023760f2614
```

该共享令牌绑定 `E3001`（王会计），具备触发审核和人工复核权限。所有使用者共用这一身份，模型调用会消耗部署者配置的 API 额度。

管理员在创空间密文 `REIMBURSE_UI_TOKENS` 中配置的完整值为

```text
E3001:62010e40f2154004b6034023760f2614
```

此登录信息由部署者提供，需与运行中的密文配置一致。令牌更换后，本节中的旧令牌会失效。

**Windows 上允许其他机器访问**：先在同一个 PowerShell 窗口配置模型密钥，再设置访问令牌并启动。

```powershell
$env:REIMBURSE_UI_TOKENS = "E3001:" + [guid]::NewGuid().ToString("N")

go run ./cmd/serve -addr 0.0.0.0:8790 -config config.example.json -data data -mcp-data data/world.json -people people.json
```

登录时使用该变量中冒号后的随机字符串。其他电脑通过服务所在电脑的实际 IP 和端口访问，网络和防火墙需要允许该端口。远程访问的身份由令牌绑定，`-local-operator` 仅对本机监听生效，`-local-demo-operators` 仅支持回环地址。


给财务共享中心做的一位 AI 同事：拿一张报销单和发票，自己查发票真伪、查企业状态、查历史重复，
按公司制度逐条判定，给出**通过 / 调整后通过 / 退回补材料 / 转人工复核 / 驳回**，并说清楚依据。

- 只做差旅（交通、住宿）与餐饮招待，只处理增值税电子发票
- 大模型只负责"看票抄字段"和"把结论写得通顺"，**判定全部由规则代码给出**
- 外部事实通过 MCP 工具核验（发票查验、企业核验、历史查重），工具在独立进程里，带令牌鉴权
- 全过程单页实时可见：每次模型调用、每次工具返回、每条规则的命中与跳过

打开 http://127.0.0.1:8790 ，左侧选一张单据，点"开始审核"。

| --- | --- | --- |
| D01 | 两个页面各审核一次，单据都是结束后第 25 天提交 | 默认制度通过 ¥553；市政国企示例命中 `R07-a`，退回说明 |
| D02 | 开始审核 → 查看任务与补件 → 粘贴 `scripts/demo-itinerary.txt` → 提交补交 → 续审 | 首轮命中 `R14-a`；第二轮通过，核准 ¥553 |
| D03 | 直接开始审核 | 发票查验超时，命中 `R15-a`，进入待人工复核 |

## 模型接入配置

启动命令见本文顶部的配置指南。

密钥只从环境变量读。配置文件里若出现 `api_key` 之类字段，程序直接拒绝启动。

默认配置走第三方网关 `api.openai-next.com`，两个模型共用一把密钥：

| 侧 | 协议 | 模型 | 说明 |
| --- | --- | --- | --- |
| DeepSeek | OpenAI 兼容 | `deepseek-v3.2` | 该网关 `deepseek-chat` 404 |
| Claude | Anthropic 兼容 | `claude-sonnet-5-5` | 网关拦非浏览器 UA，需带 `user_agent` |

端点、模型名、UA 都在 `config.example.json`，换官方接口或别的网关只改这份文件。
真实联调记录见 `docs/real-integration.md`。

## 一次审核要经过什么

```
报销单 + 发票原文 + 佐证凭证
  │
  ├─ 1. 确定范围：按规则表推导本类别适用几条规则、要调哪几个工具
  ├─ 2. 双模型抽取：DeepSeek 与 Claude 各抽一遍，逐字段比对
  │      不一致 → 该字段作废；置信度 < 0.8 → 标红；只剩一个模型 → 无交叉校验，转人工
  ├─ 3. MCP 工具核验：validate/verify/check 三类只读查询，失败或超时 → 相关判定项不作判定
  ├─ 4. 规则判定：15 条规则 / 26 个判定项，命中项全部列出，结论取最严格者
  └─ 5. 审核意见：默认由规则结果拼接；让模型润色时，生成后回查金额与条款编号
```

判定优先级：**驳回 > 转人工复核 > 退回补材料 > 调整后通过 > 通过**。

## 关键设计（评审关心的四点）

**1. 幻觉与越权**
- 模型不参与判定，只抄字段和润色文字。
- 润色后的意见会机器核对：出现判定结果里没有的金额、或没命中的条款编号，直接丢弃、退回拼接稿。
- 字段读不出、两个模型不一致、置信度不足，一律"不作判定"并转人工，不会拿猜出来的值去驳回。
- 工具只读，没有任何写操作。

**2. 过程可观测**
- 五阶段固定流水线，每步产生带序号的事件，单页实时推送（SSE）。
- 工具调用能看到原始返回，规则判定能看到"为什么命中"这一句（用实际数值写）。
- 跳过的判定项也会列出原因，人工复核知道"哪些没查"。

**3. 容错与人机边界**
- 超时是"状态未知"，既不当通过也不当"查无此票"。
- 两个模型都不用时，结论只会落在转人工。
- 三个必演场景（工具超时、单模型不可用、正常通过）见 `docs/ui.md`。

**4. 可复现与可追溯**
- 60 条用例同种子生成，内容哈希稳定。
- 规则引擎与标准答案由两条独立实现互相印证，60 条上结论、命中项、核准金额完全一致。
- 每次审核记录用了哪个模型、开了哪些开关、注入了什么故障。

## 测试

```
go test ./...
go vet ./...
```

覆盖：
- 规则引擎与标准答案逐项对照（60 条）；
- 真实模型评测（`eval -real`）：验证协议与抽取在真实网关上可用，**不代表真实票据识别能力**；
- **真实 HTTP 链路**：本地假供应商模拟 DeepSeek/Claude 的协议，跑通请求构造 → 解析 → 比对 → 判定，含单侧故障、非 JSON、字段不一致、低置信度（`internal/audit/httplink_test.go`）；
- MCP 协议工具发现与故障注入、令牌鉴权（13 项）、双模型降级、审核意见核对、SSE 事件流与页面接口。

## 边界与限制（如实说明）

1. **没有真实票据**：全部为合成数据，规则阈值是虚构值，评测数字只代表自构造测试集。
2. **真实双模型已联调，但只到"第三方网关"这一层**：模型调用与字段抽取是真的（60 条结论 60/60，
   平均 8.5 秒、$0.0101/单）；**票据是合成的，核验工具的数据也是本地 mock**。
   官方 DeepSeek / Anthropic 端点与真实税局接口均未验证。
3. **不做**：付款、改凭证、审批流引擎、真实税局查验、登录与角色权限。
6. **票据上传只支持文本型 PDF 与纯文本**：图片与扫描件需要 OCR，当前明确拒绝而不是硬猜；
   PDF 若无文本层（或字体子集缺 ToUnicode 映射）也会拒绝，转人工。上传的单据没有标准答案，
   `-demo-synthetic` 下无法审核，必须配模型密钥。
4. **令牌是静态的**：没有轮换与吊销接口；传输层未强制 TLS，跨机仅适合内网，生产要走 HTTPS。
5. **已落盘，会话仍只在内存**：任务库（`data/tasks.json`）与复核记录（`data/reviews.json`）
   跨重启保留；审核会话的事件流仍只在内存，重启后不能回放历史会话。
   工号须绑在令牌上（一令牌一人），本机可使用 `-local-operator` 绑定唯一操作人。
