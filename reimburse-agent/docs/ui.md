# 单页界面与演示脚本

一个页面讲完"AI 同事怎么工作"：左边选单据，中间看过程，右边看结论。
中间的事件流不是跑完统一回放，而是审核过程中边跑边推（SSE），评审能实时看到每一步。

## 启动

```
# 本机，无密钥演示（推荐彩排用这一条）
go run ./cmd/serve -addr 127.0.0.1:8790 -demo-synthetic

# 配了密钥：真实双模型
set DEEPSEEK_API_KEY=...
set ANTHROPIC_API_KEY=...
go run ./cmd/serve -addr 127.0.0.1:8790

# 工具走独立 MCP 进程（演示"工具在进程外"）
go run ./cmd/serve -addr 127.0.0.1:8790 -mcp-url http://127.0.0.1:8791/mcp

# 跨机访问界面：必须给界面配令牌
set REIMBURSE_UI_TOKENS=guest:请换成随机串
go run ./cmd/serve -addr 0.0.0.0:8790 -ui-token-file tokens.txt
```

跨机时打开页面会先看到登录框，粘贴令牌即可；`/api/*` 仍要求 `Authorization: Bearer`。

## 界面上的每个开关说明什么

| 控件 | 作用 | 演示时想说明的点 |
| --- | --- | --- |
| 意见：规则拼接 / DeepSeek / Claude | 让模型润色审核意见 | 默认不调模型也够用；调模型后仍会回查金额与条款编号 |
| 关闭 Claude / 关闭 DeepSeek | 模拟某模型不可用 | 只剩一个模型时，关键字段没有交叉校验，直接转人工 |
| 工具下拉（查验超时/报错等） | 注入 MCP 工具故障 | 故障时相关判定项"不作判定"，绝不落成通过 |
| 复核按钮 | 记录人工结论 | 结论写回查重库，下一张单据的查重会用到（记忆闭环） |

数据来源提示：未配密钥时会显示"合成演示数据（A/B 侧），不代表任何模型的实际能力"。
这是硬约束——录屏和现场都不能让人误以为那是真实模型输出。

## 三个必演场景（每个 40–60 秒）

**场景一：正常通过（C01 或 C03）**
1. 选 C01，点开始审核；
2. 事件流依次出现：确定范围 → 双模型抽取（每个字段一行，含置信度）→ 三个 MCP 工具调用与返回 → 逐条规则"未判定"或"命中" → 结论；
3. 右侧：通过，核准金额等于发票价税合计；
4. 点开"工具核验"，能看到查验返回的具体登记信息。**这就是"过程可观测"**。

**场景二：发票查验超时（C01 + 工具下拉选"发票查验超时"）**
1. 事件流出现 `verify_invoice 被注入 timeout`、`返回 timeout`；
2. 右侧结论变成"转人工复核"，并列出"未核验的外部事实"；
3. 讲解：超时是"状态未知"，既不当通过也不当"查无此票"，只由 R15 兜底转人工。
   **这就是"容错"**。

**场景三：一个模型不可用（C24 或 C52 + 勾选"关闭 Claude"）**
1. 事件流里 Claude 直接报"已被演示开关关闭"；
2. 关键字段没有交叉校验 → 命中 R15-b → 转人工；
3. 讲解：单模型不确定的东西不猜，交给人。**这就是"人机协作边界"**。

补充可选场景：**C51（发票查验超时，但单据本身干净）**—— 说明即使所有字段都读对了，
只要有一个外部事实没核验，也不会自动通过。

## 复核回写（记忆）怎么演示

1. 跑完 C01，点"确认通过"，填意见"票据齐全"；
2. 打开 `/api/reviews` 或再跑一次同一张单据；
3. 讲解：结论已写入查重库，下次遇到同一张发票会命中 R04-a 重复报销。
   这是"记忆"落在业务上的样子，而不是存一段对话历史。

## 接口一览（便于用 curl 自测或对接别的界面）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/cases` | 60 条用例摘要 |
| GET | `/api/cases/{id}` | 单据明细（报销单、发票原文、凭证原文） |
| POST | `/api/audit` | 启动审核，返回 `session_id`；可带 `disabled` / `faults` / `explain` |
| GET | `/api/audit/{sid}/events` | SSE：`snapshot` → `event`* → `report` → `done` |
| GET | `/api/audit/{sid}` | 会话快照（刷新或重连用） |
| POST | `/api/review` | 记录人工复核结论 |
| GET | `/api/reviews` | 复核记录 |
| GET | `/api/meta` | 模型、密钥状态、规则版本、工具接入方式 |
| GET | `/api/stats` | 本次运行累计：单量、结论分布、成本 |

## 已知限制

1. 会话只存在内存里，服务重启后历史会话与复核记录丢失。演示够用，生产要落库。
2. 没有登录与角色区分。跨机访问只靠一个界面令牌，不区分"审核员"和"只读"。
3. 事件流不做持久化回放，只能通过 `/api/audit/{sid}` 读当前进程内的会话。
4. 前端未做无障碍适配（键盘导航、屏幕阅读器）。
