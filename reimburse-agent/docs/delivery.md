# 交付清单

> 交付日期：2026-11-18　交付形态：单个可执行文件 + 数据 + 文档，无需数据库与外部服务

## 一、怎么开始（30 秒）

```
# 解压 dist 目录后，在该目录执行：
reimburse-agent.exe -addr 127.0.0.1:8790 -demo-synthetic
```

浏览器打开 `http://127.0.0.1:8790`，左侧选一张单据 → 点「开始审核」。

`-demo-synthetic` 是**无密钥演示模式**：字段抽取由测试集标准答案合成，
判定链路完全真实，界面与报告都会标注「合成演示数据」。
配好密钥就去掉这个参数，自动改走真实模型。

## 四、测试与验证（可复跑）

```
go test ./...        # 9 个包全绿
go vet ./...         # 无告警
gofmt -l .           # 无差异

go run ./cmd/eval -out docs        # 60 条评测，结论/命中项/金额三项全对
go run ./cmd/rehearse -out docs    # 4 场景彩排
```

已验证的具体结论：

- 规则引擎与标准答案由两条独立实现推出，60 条上完全一致（`TestEngineMatchesLabelOnAllCases`）
- 真实 HTTP 链路（本地假供应商模拟两家协议）60 条全通（`TestHTTPLinkAllCases`）
- 12 类脏输入不崩溃且不给出"通过"（`TestRobustnessOnBadInputs`）
- 工具故障、模型不可用、字段不一致、低置信度，结论只会落在转人工
- 跨机访问实测：无令牌 401、错令牌 401（只回指纹）、正确令牌 200 并跑完整单

## 五、已知限制（如实声明）

1. **无真实票据**：全部为合成数据，规则阈值虚构，评测数字只代表自构造测试集。
2. **真实双模型已联调（第三方网关）**：60 条结论 60/60、核准金额 19/19、命中项 59/60，
   平均 8.5 秒、$0.0101/单；4 场真实彩排全过。官方端点与真实票据仍未验证，
   详见 `docs/real-integration.md` 与 `docs/eval-real.md`。
3. **不做**：付款、改凭证、审批流引擎、真实税局查验、登录与角色权限。
4. **令牌为静态**：无轮换与吊销接口；传输层未强制 TLS，跨机仅适合内网。
5. **已落盘，会话仍只在内存**：任务库与复核记录跨重启保留（`data/tasks.json`、`data/reviews.json`），
   审核会话的事件流仍只在内存，重启后不能回放历史会话，生产需接真正的存储。

## 六、密钥与复跑

密钥只放环境变量。默认配置走第三方网关，两把变量填同一个值：

```
set DEEPSEEK_API_KEY=<网关密钥>
set ANTHROPIC_API_KEY=<网关密钥>

# 真实评测（约 10 分钟，120 次模型调用）
go run ./cmd/eval -real -config config.example.json -out data/eval-real

# 真实彩排
go run ./cmd/rehearse -real -config config.example.json -out data/rehearsal-real

# 单张单据
go run ./cmd/audit -case data/cases/C01 -config config.example.json
```

剩下要人工做的：录一份真实模型的演示备份视频，替换 `docs/demo.mp4`。

如果真实评测出现明显偏差，优先看两个地方：
一是 Prompt 里金额/日期的格式约束是否被模型遵守（看事件流里每个字段的合并值）；
二是 `docs/eval.md` 的失败用例表，那里会直接列出漏判与误判的判定项编号。
