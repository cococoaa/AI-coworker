# 用量配额与人员身份

> 两个上线前的必要件：**成本失控**和**追不到人**。
> 前者防的是钱，后者防的是"错了没法改、改了不知道谁改的"。

---

## 一、用量配额

### 为什么不能只设一个月/周总量

先看真实数字：**平均 $0.0101/单**，Claude 占约 90%。按 200 单/工作日算是 $2/天，一周约 $10。

只设周总量会漏掉两类问题：

| 问题 | 周总量能发现吗 |
| --- | --- |
| 某张发票超长（OCR 重复行压进去），单次调用 100 倍开销 | 不能，淹没在总量里 |
| 重试风暴 / 脚本刷接口 | 要等到周末才发现 |

所以是**三层**：

| 层 | 阈值 | 抓什么 |
| --- | --- | --- |
| 单次请求 | `max_tokens=4096` | 输出爆炸 |
| 单张单据 | $0.05（正常 $0.01，5 倍即异常） | 重试风暴、超长文本 |
| 周总量 | $50（正常 $10 的 5 倍） | 整体失控 |

周总量三档：**70% 预警 / 90% 严重 / 100% 熔断**。

### 熔断后做什么：不降级，只转人工

这是整个方案里唯一不能商量的地方：

```
预算耗尽 → 停止自动判定 → 全部转人工 → 报警 → 保留只读查询
```

**绝不用更便宜的模型凑合判一个结论。** 那是拿准确率换成本，而准确率下降的后果是**错批**，在财务系统里不可逆。省几毛钱，赔一张错单。

一句话：**积压是可见的，错批是不可见的。**

这与系统里已有的设计一脉相承——工具超时 → 转人工；字段不可信 → 转人工。预算超支走同一条路。

### 成本与自动化率是对立的

Claude 占 90% 成本，想省钱只有一条路：关掉 Claude 只用一个模型。但关掉就触发 R15-b（无交叉校验）→ 全部转人工。

所以**"省钱"和"自动化率"不能两个都要**。这个账要提前算清楚，不能等到熔断了才发现。

### 落盘

周用量写在 `data/quota.json`，原子写（临时文件 + rename），不需要数据库。跨重启保留，跨周自动开新桶（ISO 周，周一为起点），保留最近 8 周。

### 实际操作

```bash
# 正常启动（周预算 $50）
reimburse-agent.exe -addr 127.0.0.1:8790 -quota-file data/quota.json -weekly-budget 50

# 演示熔断：把本周已用量预置到 99%（不用真跑几百单）
reimburse-agent.exe -addr 127.0.0.1:8790 -seed-usage 49.5 -seed-client E3001

# 不限预算（不推荐，只用于测试）
reimburse-agent.exe -addr 127.0.0.1:8790 -weekly-budget 0
```

界面上：顶部显示"本周 $X / $50（Y%）"，超 100% 变红并禁用「开始审核」；接口返回 429。

### 实测记录

```
预置 $49.5077（99.0%）→ level=critical，仍放行（正确：没到 100%）
再跑一单 → $49.5154（99.0%），仍放行
补到 $50.1258（100.3%）→ level=blocked
  POST /api/audit → 429
  {"error":"本周 AI 用量已达上限，自动审核已熔断",
   "action":"该单据需转人工处理；请等待下周预算刷新或由管理员调整预算"}
  界面：徽章变红、开始审核按钮禁用
```

## 二、人员身份：工号 + 令牌

### 为什么令牌不够

**令牌是机器凭证，不是人的身份。**

- 令牌属于"一个调用方"（一条部署、一个脚本），不属于"张三"
- 令牌会共享、写进配置文件、复制给同事"帮我跑两单"
- 用 scope 做角色，角色就跟着令牌走：令牌一共享，角色静默转移，日志里只剩 `client: reviewer`，说不清是谁

而复核结论会写进查重库、影响后续单据，**必须能追到人**。

### 为什么不做 RBAC

当前暴露的写操作只有两个："触发审核"和"写复核结论"。真正的职责分离（谁能改制度）已经在服务器访问权那一层——改阈值要改 JSON 并重启进程，Web 层根本碰不到。

硬做 scope 只会做出一个看起来像权限、实际追不到人的假角色。**假角色比没有角色更危险**：演示时一被追问"三个人在日志里怎么区分"，就答不上来。

### 最小方案：30–50 行的身份层

```
令牌  →  证明"这个部署允许访问"     （mcpauth，已有）
工号  →  证明"这件事是谁做的"        （identity，新增）
```

- 工号名单来自 `people.json`，**不由前端自称**（前端传什么就是什么，等于没有身份）
- 两个权限位就够：`can_audit`（能否触发审核）、`can_review`（能否提交/撤销复核）
- 名单文件不存在或为空时，**拒绝一切复核写入**——默认拒绝，不是默认放行

```json
{
  "people": [
    {"employee_id":"E3001","name":"王会计","dept":"财务共享中心","can_review":true,"can_audit":true},
    {"employee_id":"E3003","name":"内审-只读","dept":"审计部","can_review":false,"can_audit":true},
    {"employee_id":"E3004","name":"张三（已离职）","can_review":true,"disabled":true}
  ]
}
```

### 实测

```
无工号复核          → 403 工号不在授权名单中
未知工号 E9999      → 403
只读账号 E3003      → 403 工号 E3003（内审-只读）没有复核权限
离职账号 E3004      → 403 工号 E3004 已停用
正确工号 E3001      → 200，日志记录 operator=E3001 / 王会计
```

## 三、复核结论可撤销

### 问题

`/api/review` 是系统里**唯一会悄悄改变业务状态**的接口：复核结论写进查重库（`extraHistory`），下一张单的查重会命中它。

如果复核人点错了"确认通过"，那张发票以后就会被判"已报销过"。只追加不撤销的日志，等于错了没法改。

### 做法：软删除 + 回滚

- 记录**不删除**，只标记 `revoked_at` / `revoked_by` / `revoke_reason`
- 同时把查重库里的对应记录撤掉（`AffectedHistory` 记着写的是什么）
- 审计能看到"谁批的、谁撤的、为什么撤"

### 还有一处语义修正

**只有"通过 / 调整后通过"才写查重库。**

驳回的结论代表这张票不该报，写进去反而会让它以后被判"已报销过"，语义是错的。这个 bug 在实现时发现并修掉了，有测试锁住（`TestRejectDoesNotAffectDedup`）。

### 界面

复核区加了醒目提示：

> ⚠️ 选择「通过」或「按核准金额通过」会把这张发票写入查重库，此后同一张发票会被判为**重复报销**。写错了可以撤销。

提交后返回 `impact` 字段，直接告诉前端"这条结论做了什么"；撤销后同样返回"已从查重库撤掉"。

### 实测

```
提交 approve（E3001）→ 200，impact: "已写入查重库：发票 2637... 将被标记为已报销过"
撤销（E3001，原因"看错了"）→ 200，impact: "已撤销，并从查重库撤掉对应记录"
撤销后：查重库回写条数 = 0；记录仍在，revoked_at 有值，revoked_by=王会计
复核 reject → 查重库回写条数 = 0（正确，驳回不写）
```

## 四、接口变更

| 方法 | 路径 | 变化 |
| --- | --- | --- |
| POST | `/api/audit` | 新增配额预检；超限返回 429（附带 `quota` 与 `action`） |
| POST | `/api/review` | 必须带 `employee_id`；返回 `impact` 说明对查重库的影响 |
| POST | `/api/review/revoke` | **新增**：撤销复核结论并回滚查重库 |
| GET | `/api/reviews` | 返回含撤销状态 |
| GET | `/api/quota` | **新增**：本周用量、档位、分桶、告警 |
| GET | `/api/people` | **新增**：可选操作人（过滤停用账号） |

## 五、边界

**做**：周预算三档控制、按调用方分桶、落盘、熔断转人工；工号身份校验、离职停用、只读账号；复核可撤销、驳回不写查重库。

**不做**：RBAC、组织架构树、SSO、按部门分账、跨周预算结转。这些是产品化才需要的，现在加进去只会让演示多几个失败点。

**已知限制**：
- 工号靠前端配合传，未做真正的登录会话（会话伪造仍可能，需配合令牌使用）
- 令牌与工号没有绑定关系，同一令牌可配多个工号
- 配额按 ISO 周硬切，不支持按自然月或财年
- 告警只落在接口与界面，**没有对接邮件/IM**（按需再接）
