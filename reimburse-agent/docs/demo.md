# 现场演示手册

> 目标：50 秒内讲清"它是什么、它怎么做、它出错时怎么办"。
> 每一句都可以照着念，不必临场组织语言。

## 开场（10 秒）

> 财务每天要审几百张差旅餐饮报销单：抄发票、查验真伪、查企业状态、查重复、对制度。
> 规则明确但很耗人。我们做了一位 AI 同事：**它做核查和初判，人只处理真正需要判断的单据。**

## 主场景：一张正常单据（40 秒）

1. 左侧选 **C01（普通员工乘高铁二等座，材料齐全）**，点「开始审核」。
2. 边跑边说：

> 五个阶段：确定范围 → 双模型抽取 → 工具核验 → 规则判定 → 出意见。
> 抽取是 DeepSeek 和 Claude **各抽一遍**，逐个字段比对；不一致、置信度低于 0.8 的字段直接作废，不许猜。
> 三个工具走 **MCP 协议**，是独立进程：发票查验、企业核验、历史查重。**只读，一个写操作都没有。**

3. 指针停在事件流里某条工具返回上：

> 这是工具真实返回的内容，不是我们转述的。

4. 右侧结论：

> 通过，核准金额等于发票价税合计。每条命中项都写着**为什么**——用的是这张单据的实际数字。
> 没有命中的判定项也列出来了，人复核时知道"哪些查了、哪些没查"。

## 故障场景一：查验超时（30 秒）

选 C01，工具下拉切到「发票查验超时」，再点审核。

> 查验超时了。注意结论：**转人工**，不是通过，也不是驳回。
> 超时是"状态未知"——既不能说票是真的，也不能说查无此票。这类单据我们只做一件事：交给人。

## 故障场景二：一个模型不可用（30 秒）

选 **C03（住宿）**，勾选「关闭 Claude」，再点审核。

> Claude 挂了。DeepSeek 还能抽，但关键字段**没有第二个人核对**了。
> 所以结论还是转人工：单个模型说什么，我们不全信。
> 这就是人机边界——不确定的交给人，不是让模型赌一把。

## 能力边界（20 秒，被问到时说）

> 它能：抽字段、查外部事实、按制度判初判、写意见。
> 它不能：付款、改凭证、冲销发票、替人做最终决定。
> 意见文字默认由规则结果拼接，金额和条款不经模型；就算让模型润色，生成后还会机器核对一遍：
> 出现判定结果里没有的金额或条款编号，直接丢弃重来。

## 权限与安全（被问到时说）

> 工具全部只读，按最少条件查、不整库返回。
> 服务默认只听本机；跨机必须带 Token，没配 Token 服务直接拒绝启动。
> 日志只记"谁调的、从哪个 IP、什么时候"，不记发票内容，也不记 Token 本身。

## 常见提问的标准回答

**Q：模型乱说怎么办？**
A：判定不是模型做的。模型只抄字段，抄不确定的字段会被标记作废；判定是 15 条规则、26 个判定项的确定性代码。
意见文字也要过核对。

**Q：数据从哪来？**
A：现在是我们自己生成的 60 条带标准答案的测试集，规则阈值是虚构的。
真实数据要接的话，只改工具后端那一层，接口已经定好了。

**Q：现在准确率多少？**
A：60 条测试集上，结论、命中项、核准金额 100% 一致——但这只证明**判定链路**是对的，
不证明模型在真实票据上的抽取准确率。那个数字要等接了真实密钥、跑真实票据才有。

**Q：为什么不用 Agent 自由规划？**
A：报销审核是对错分明的业务。让模型自己决定查什么、什么时候停，就存在"跳过必查项也能给出通过"的风险。
我们用固定五步流水线，保证必查项一个不漏，同时每一步都可观测。

**Q：成本多少？**
A：单张约 \$0.002–0.004，几分钱。界面每次审核都显示实际估算成本。

## 演示失败时怎么办

| 情况 | 处理 |
| --- | --- |
| 页面打不开 | 用 `reimburse-agent.exe` 重新起，端口换成 8793；实在不行播备份视频 |
| 审核卡住超过 10 秒 | 直接讲事件流已出现的内容，再点一次审核 |
| 没有密钥、界面提示"合成数据" | 这是预期行为，照常讲；并说明"合成只影响抽取，判定链路完全真实" |
| 现场断网 | 本地无依赖，工具是进程内的，断网不影响 |
| 电脑崩了 | 备份视频 + 静态截图（见下） |
